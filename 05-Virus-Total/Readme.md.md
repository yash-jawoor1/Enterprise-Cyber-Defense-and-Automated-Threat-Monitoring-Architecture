
# VirusTotal Integration with Wazuh — SOC Lab Notes

Project documentation · Wazuh 4.14.9 · VirusTotal · Windows 11 Endpoint

## 1. Introduction

In a modern Security Operations Center (SOC), analysts receive numerous security alerts every day. However, an alert alone does not always provide enough information to determine whether a file is malicious or legitimate.

Threat Intelligence helps solve this problem by enriching security alerts with information from external threat intelligence platforms.

VirusTotal is a threat intelligence platform that analyzes files, URLs, domains and IP addresses using multiple security vendors and detection engines.

By integrating VirusTotal with Wazuh, analysts can automatically check the reputation of files detected on monitored endpoints.

### Objectives

- Integrate VirusTotal with Wazuh Manager.
    
- Configure File Integrity Monitoring (FIM) on a Windows endpoint.
    
- Automatically submit file hashes for VirusTotal reputation lookups.
    
- Enrich Wazuh alerts with threat intelligence.
    
- Validate the integration through real-time file activity.
    

Security note: Avoid uploading confidential or proprietary files to VirusTotal. Files and submitted information may be shared with VirusTotal's security partners and other users.

## 2. Understanding the integration

VirusTotal provides several useful capabilities:

1. File hash reputation lookup.
    
2. Malware detection information from multiple antivirus engines.
    
3. File metadata and analysis information.
    
4. URL and domain reputation checks.
    
5. API-based automated threat intelligence lookups.
    

In our lab, we use the VirusTotal API to check file hashes generated by Wazuh FIM.

### How the integration works

Windows 11 Endpoint

A file is created, modified or deleted

File activity

Wazuh Agent — FIM

Detects file changes and calculates hashes

Syscheck event and file hash

Wazuh Manager

Processes the alert and triggers integration

API request using file hash

VirusTotal API

Checks the file hash against its database

Threat intelligence response

Wazuh Dashboard

Displays the VirusTotal enrichment alert

### Explanation of each stage

|Component|Responsibility|
|---|---|
|Windows Endpoint|Generates file activity|
|Wazuh Agent|Monitors files using FIM|
|Syscheck|Calculates file hashes|
|Wazuh Manager|Processes events and runs integration|
|VirusTotal API|Checks hash reputation|
|Wazuh Dashboard|Displays the enriched result|

Important: The integration performs a hash reputation lookup. It does not automatically upload every file to VirusTotal.

## 3. Step 1 — Obtain a VirusTotal API key

1. Visit [VirusTotal](https://www.virustotal.com/?utm_source=chatgpt.com).
    
2. Create an account or sign in.
    
3. Open your profile.
    
4. Navigate to the API Key section.
    
5. Copy your personal API key.
    

Keep your API key private. Never publish it in GitHub repositories, screenshots or public documentation.

## 4. Step 2 — Configure VirusTotal integration on Wazuh Manager

Our Wazuh Manager runs on Linux, so its configuration file is:

```
sudo nano /var/ossec/etc/ossec.conf
```

Add the following block inside the main `<ossec_config>` element, before its closing tag:

```
<integration>
  <name>virustotal</name>
  <api_key>YOUR_API_KEY</api_key>
  <group>syscheck</group>
  <alert_format>json</alert_format>
</integration>
```

Replace `YOUR_API_KEY` with your actual VirusTotal API key.

### Explanation of the configuration

|Parameter|Purpose|
|---|---|
|`name`|Enables the VirusTotal integration|
|`api_key`|Authenticates requests to VirusTotal|
|`group`|Triggers integration for syscheck alerts|
|`alert_format`|Sends alerts in JSON format|

The `syscheck` group is important because it allows VirusTotal integration to process file integrity monitoring events.

### Validate the configuration

```
sudo /var/ossec/bin/wazuh-analysisd -t
```

Restart Wazuh Manager:

```
sudo systemctl restart wazuh-manager
```

Check service status:

```
sudo systemctl status wazuh-manager
```

Check integration process:

```
sudo /var/ossec/bin/wazuh-control status
```

Look for:

```
wazuh-integratord is running
```

## 5. Step 3 — Configure File Integrity Monitoring on Windows

The Windows endpoint must monitor a directory for file changes.

Our test directory:

```
C:\VT-Test
```

Open the Wazuh Agent configuration file on Windows:

```
C:\Program Files (x86)\ossec-agent\ossec.conf
```

Find the existing `<syscheck>` section and add:

```
<directories realtime="yes">C:\VT-Test</directories>
```

For example:

```
<syscheck>
  <disabled>no</disabled>
  <frequency>43200</frequency>

  <directories realtime="yes">C:\VT-Test</directories>

</syscheck>
```

### Explanation

|Parameter|Purpose|
|---|---|
|`disabled=no`|Enables FIM|
|`frequency=43200`|Periodic scan interval of 12 hours|
|`realtime=yes`|Enables real-time monitoring|
|`C:\VT-Test`|Directory monitored by Wazuh|

Restart the Windows agent using PowerShell as Administrator:

```
Restart-Service WazuhSvc
```

Verify the service:

```
Get-Service WazuhSvc
```

### Verify FIM monitoring

Check the agent log:

```
Get-Content "C:\Program Files (x86)\ossec-agent\ossec.log" -Tail 30
```

Look for messages indicating:

```
Real-time file integrity monitoring started.
Monitoring path: 'c:\vt-test'
```

## 6. Step 4 — Troubleshooting internet connectivity

During our integration, VirusTotal requests initially failed because the Wazuh server had no default route.

The Wazuh server could communicate with pfSense but could not reach external networks.

### Identify the issue

```
ip route
```

The default route was missing.

### Configure the default route

Our network configuration:

|Device|IP address|
|---|---|
|pfSense LAN|`192.168.1.1`|
|Wazuh Manager|`192.168.1.128`|

We added:

```
sudo ip route add default via 192.168.1.1 dev eth0
```

Verify:

```
ip route
```

Expected:

```
default via 192.168.1.1 dev eth0
```

Test internet connectivity:

```
ping -c 4 8.8.8.8
```

Test DNS:

```
getent hosts www.virustotal.com
```

Test HTTPS:

```
curl -I --connect-timeout 15 https://www.virustotal.com
```

All these tests subsequently succeeded.

Important

The `ip route add` command creates a temporary route. It may disappear after reboot. Persistent route configuration remains a separate task.

## 7. Step 5 — Verify VirusTotal API connectivity

We tested both VirusTotal API versions.

### API v3 test

The API v3 request uses the `x-apikey` HTTP header.

```
headers = {    "x-apikey": API_KEY,    "accept": "application/json"}response = requests.get(    "https://www.virustotal.com/api/v3/files/HASH",    headers=headers)
```

Our API v3 test returned HTTP 200.

### API v2 test

Our installed Wazuh integration script uses the older API v2 endpoint:

```
https://www.virustotal.com/vtapi/v2/file/report
```

We tested it successfully and received:

```
HTTP Status: 200
response_code: 1
positives: 66
```

This confirmed that the API key, network connectivity and legacy endpoint were working.

Why did the initial request fail?

The initial API request failed with `Network is unreachable` because the default route was missing. After adding the route, the same API request worked.

## 8. Step 6 — Validate File Integrity Monitoring

Now we test whether Wazuh detects file creation, modification and deletion.

Open Windows PowerShell.

Run the following commands:

```
$file = "C:\VT-Test\fim-validation.docx"

# Create file
Set-Content $file "Initial content for Wazuh FIM validation"

Start-Sleep -Seconds 3

# First modification
Add-Content $file "First modification"

Start-Sleep -Seconds 3

# Second modification
Add-Content $file "Second modification"

Start-Sleep -Seconds 3

# Delete file
Remove-Item $file
```

### Expected Wazuh alerts

|Activity|Wazuh rule ID|Severity|
|---|---|---|
|File created|554|5|
|File modified|550|7|
|File deleted|553|7|

### How to verify alerts in the Linux server

```
sudo grep -i 'fim-validation.docx' /var/ossec/logs/alerts/alerts.json
```

This displays the events associated with the test file.

## 9. Step 7 — Validate VirusTotal integration

We performed a separate test by creating a file in the monitored directory.

On Windows PowerShell:

```
Set-Content "C:\VT-Test\virustotal-check.txt" "VirusTotal integration test"
```

Wazuh detected the newly created file.

### File Integrity Monitoring alert

The manager generated:

```
Rule ID: 554
Description: File added to the system.
Group: syscheck
```

The event contained:

- File path
    
- File size
    
- MD5 hash
    
- SHA1 hash
    
- SHA256 hash
    
- File event type
    

### VirusTotal response

After processing the FIM event, Wazuh queried VirusTotal and generated another alert:

```
Rule ID: 87103
Description: VirusTotal: Alert - No records in VirusTotal database
Group: virustotal
```

The response included:

```
{
  "virustotal": {
    "found": "0",
    "malicious": "0",
    "source": {
      "file": "c:\\vt-test\\virustotal-check.txt"
    }
  },
  "integration": "virustotal"
}
```

### Understanding the result

- `found: 0` — VirusTotal did not find a matching record.
    
- `malicious: 0` — No malicious detections were returned.
    
- `integration: virustotal` — The result was generated by the VirusTotal integration.
    

This confirms successful integration. It does not prove that the file is completely safe; an unknown hash can simply mean that the file has not been analyzed before.
